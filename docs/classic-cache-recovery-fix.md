# 经典版旧图片缓存恢复修复

部署基准：`54da197`，分支：`codex/image-async-recovery`。本次针对经典版/VIP 的旧图显示过期、缓存空间不足，而画布仍可读取同图的回归。

## 已复现的原因

1. 共享缓存把不受它管理的旧画布资产也计入原图预算。浏览器还有可用磁盘空间时，也可能因为应用自己的预算而拒绝经典版写入。
2. 经典版通过复制原图迁移旧缓存；写入失败时，旧数据库仍有原图/预览，新读取器却找不到它们。账号旧历史规范化时还可能丢失原缓存键。
3. 画布的精确图片 URL → 旧资产 ID 关联没有被经典版读取。服务器临时链接过期后，经典版只尝试远程读取，画布则仍有本地原图。
4. 原图和预览共用一个预算，原图预算用满后，小预览也无法持久化。状态文案还会用“原图过期”覆盖已有预览的事实。
5. 本地历史会先于网络返回显示，但图片元数据只在其他恢复路径登记；冷启动时卡片可能在关联完成前就读取失败。

这些路径均有失败后通过的回归测试。它们解释了截图中的组合症状；具体用户的每张旧图是否仍有本地副本，需要在原浏览器验证。

## 修复行为

- 旧经典缓存直接按保留的旧 ID 读取，不为读取再复制一份原图。共享缓存读取暂时失败时也尝试旧经典缓存。
- 在卡片首次读取前登记其明确的账号、任务和输出信息；移除卡片、重新绑定或切换账号会丢弃过期的异步绑定。
- 对当前账号记录提供的精确原图 URL，链接已有画布缓存。登记、徽标检查仅访问键和小型元数据，不批量读取原图 Blob，不按提示词猜测关联。
- 链接明确校验记录账号，拒绝把另一个稳定结果 ID 当作旧画布资产，并在同一事务内核对源是否存在及设置共享保护。
- 共享缓存只计算自己管理的稳定结果。桌面原图预算 384 MiB、预览独立预算 64 MiB；移动端分别为 128 MiB、24 MiB。浏览器真实磁盘配额依然由浏览器决定。
- 回收只影响超出预算的图片版本，保留另一版本的元数据。过期、来源不明及正在读取的本地副本继续受保护。
- 原图保存和下载逐张处理；完成后补齐预览，即使原图预算不足仍可尝试保存小预览。优先使用服务器小预览；自动下载在预览准备前发起，不等待预览网络读取。
- 画布制作旧图预览时，在提交事务里合并最新元数据，保留其他标签页刚设置的共享标记。清理时在同一读写事务检查保护并删除，防止先检查后删除的跨标签页竞态。
- 已有本地原图不会仅因云端过期而提示需要恢复；只有预览时明确显示“仅预览已缓存 · 云端原图已过期，可从本地文件恢复”。

服务器临时保存期限、扣点、任务状态和退款流程不需要变更。云端 4 小时提示及实际 5 小时缓冲沿用现有配置。浏览器缓存与系统下载文件独立；网页不能自动扫描系统下载目录。

## 验证

本地真实 Chrome 使用模拟接口，不发起付费生成：40 条含 3840×2160 原图、720×405 预览的旧记录，分别来自经典数据库与画布数据库。所有远程图片链接返回 410，并额外加入 512 MiB 旧画布元数据以触发旧版预算错误（不实际分配 512 MiB）。

- 桌面仍为 24 张/页；可见卡片从本地预览恢复，全部卡片显示本地原图已缓存。
- 云端图片请求为 0；首屏原图读取为 0；预览解码并发峰值为 1。
- 刷新后反复往返翻页，读取失败为 0，活动 Object URL 峰值为 5，未持续累积。
- 按需读取的原图为 164951 字节，稳定 ID 下没有重复原图。
- 新原图不再被那条非托管旧元数据阻挡。
- 实时生成区分别选中两条旧记录、重新加载页面，当前图片继续恢复；另用受限真实 IndexedDB 验证原图配额错误后预览依然可以持久化。

另有自动化回归覆盖原图预算用满后的预览保存、只回收原图后画布离线读取预览、共享源在解码期间被另一个标签页关联、共享关联与清理同时发生、缺失源的陈旧别名、账号切换、双标签自动下载领取。

最终验证：Node 106 项、Vitest 62 项均通过；TypeScript、脚本语法检查及生产构建通过。独立审查发现的元数据保留和跨标签页竞态已修复并补齐回归，没有剩余严重或重要问题。

实际设备的内存占用取决于图片大小和浏览器。本次测试验证了读取、并发、资源释放及恢复路径，不承诺所有设备永不发生内存不足。

## 更新与用户验收

```bash
cd /www/wwwroot/aigc.aittco.com
git status --short
git fetch origin
git switch codex/image-async-recovery
git pull --ff-only origin codex/image-async-recovery
docker compose up -d --build app
docker compose ps
docker compose logs --tail=100 app
git log -1 --oneline
```

保留服务器本地配置和数据；存在本地 Git 修改时先核对保存。部署后在原来保存图片的同一浏览器、同一账号按 Ctrl+F5，只重新加载前端文件，**不要清除网站数据或 IndexedDB**。经典版变更脚本版本为 `classic_cache_v3`。

1. 查看昨晚的两张动物运动会图片及旧画廊：浏览器仍有对应旧缓存的，应恢复显示。
2. 刷新、离开画廊再进入、往返翻页：已有图片继续读取本地预览，不反复跳动或整页重新下载原图。
3. 核对徽标：有原图显示“原图已缓存（本浏览器）”，只有预览时不能宣称原图已保存。
4. 新生成一张图，核对浏览器下载记录；刷新后预览仍可显示。
5. 本地从未保存或已被清理，且云端也已经过期的原图，需要选择之前下载的文件恢复。只有预览不能还原原图。
