# 生图请求等待修复

线上案例：2026-10-12 21:50:41（北京时间），受影响账号的 GPT Image 2 线路二编辑请求已进入计费。不能用未退款推断生图成功，也不能用没有 pending 任务推断浏览器收到结果。

已复现的缺陷：经典版提交 fetch 和轮询 fetch 无请求超时；轮询的总期限只有在下一轮开始时才检查。画布版在提交前开始模拟百分比，成功状态无图片时停止轮询却不结束 loading。编辑接口缺少生成记录，结果无法像普通生成任务一样从历史记录恢复。

修复范围：
- 提交快速返回任务的线路等待上限 120 秒；仍同步返回结果的线路保留 25 分钟窗口，避免正常长任务提前中断。查询请求及 JSON 响应体均限制在 20 秒。
- 超时只终止浏览器等待，不自动重新提交或退款；提示结果未确认，先查历史以避免重复扣点。
- 经典版查询总期限独立计时；停止后忽略晚到响应。画布版图片任务总等待限制 30 分钟，成功但无图片给出明确异常。
- 画布图片占位改为提交/等待结果和等待时长，不再显示模拟百分比。视频显示行为保持现有方式。
- 编辑任务保存 PENDING 记录、客户端占位 ID、任务 ID、最终结果和错误；刷新经典版后可以恢复。此修复不能补造过去未记录的编辑结果。
- 提供服务器上的只读诊断命令，用计费 ID 联查 task ID、状态和生成记录，以便定位原案例及后续案例。

验证：回归测试覆盖 fetch 永不响应、JSON 永不完成、晚到响应、成功无 URL、任务总期限、编辑后台成功/失败/直接结果。构建通过后交付可部署代码；上线后的上游状态仍需服务器记录确认。
