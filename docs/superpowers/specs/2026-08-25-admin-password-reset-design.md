# 管理员重置用户密码设计

## 背景

当前系统已有普通用户修改自己的密码、邮箱验证码找回密码，以及后台用户资料管理能力，但后台没有管理员代用户重置密码的入口。目标是在不暴露密码、不绕过现有密码策略的前提下，让管理员在用户详情页输入并确认新密码。

## 目标与范围

- 管理员可在后台用户详情页为指定用户设置新密码。
- 重置密码沿用现有 `validatePassword` 规则：长度 8–200 个字符；不新增字母/数字组合要求。
- file 存储和 MySQL 存储行为一致。
- 重置后使目标用户现有会话全部失效，目标用户必须使用新密码重新登录。
- 不改变普通用户自身改密、邮箱验证码找回密码、用户资料编辑和点数调整流程。

## 权限模型

- 请求必须经过已登录管理员认证。
- 普通管理员只能重置普通用户密码。
- 超级管理员可重置普通用户、管理员和超级管理员密码。
- 服务端根据当前操作者和目标用户角色再次校验权限，前端按钮隐藏/禁用不作为安全边界。
- 管理员不能通过该接口获取明文密码；响应只返回更新后的公开用户信息和用户详情。

## 方案

新增独立接口，避免把敏感动作混入资料更新：

```text
POST /api/admin/users/:userId/password
Authorization: 当前管理员会话
Body: { "password": "..." }
Response: AdminUserDetailPayload
```

服务端流程：

1. 使用现有 `requireAdminAccess` 获取操作者。
2. 查询目标用户；不存在返回 `USER_NOT_FOUND`/404。
3. 根据目标角色执行普通管理员/超级管理员权限判断。
4. 调用现有密码校验和 scrypt 哈希逻辑写入新密码及更新时间。
5. 删除目标用户的全部会话（file 删除内存/文件中的 session，MySQL 删除 `auth_sessions` 行）。
6. 返回与现有用户详情接口相同的安全 payload，确保不包含密码哈希。

前端在 `UserAdminPanel` 的用户资料区域新增重置表单：新密码、确认密码、提交按钮。输入为空、两次不一致或后端策略校验失败时显示错误；提交期间禁用按钮；成功后清空输入、刷新详情并显示 Toast。普通管理员对管理员目标用户不显示可用的提交入口，但仍由服务端拒绝越权请求。

## 错误处理

- 未登录：复用 `AUTH_LOGIN_REQUIRED`。
- 非管理员：复用 `ADMIN_REQUIRED`。
- 普通管理员重置管理账号：新增明确的 `ADMIN_PASSWORD_RESET_FORBIDDEN`（HTTP 403）。
- 用户不存在：复用 `USER_NOT_FOUND`（HTTP 404）。
- 密码不符合现有规则：复用 `INVALID_PASSWORD`（HTTP 400）。
- 其他存储错误：沿用现有 `sendAuthError`/500 处理，不回显密码或哈希。

## 测试策略

先写失败测试，再实现：

- file 存储：超级管理员重置任意用户成功；普通管理员重置普通用户成功；普通管理员重置管理员被拒绝；新密码可登录；旧会话失效；短密码被拒绝。
- MySQL 存储：覆盖同样的权限、哈希、会话失效和校验行为，使用现有数据库测试约定。
- HTTP/服务层：验证新路由调用管理员鉴权、返回安全 payload，并正确映射 403/404/400 错误。
- 前端服务/组件：验证请求 body 只提交新密码、确认密码不发送；成功后清空表单并刷新详情；不满足权限时不允许提交。

## 不做的事情

- 不生成临时密码。
- 不发送邮件或短信通知。
- 不修改普通用户自助找回密码流程。
- 不新增密码复杂度规则或密码历史策略。
