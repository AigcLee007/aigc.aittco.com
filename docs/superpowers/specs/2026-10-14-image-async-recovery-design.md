# 全线路生图异步与断网恢复设计

保留期更新：2026-10-15 用户改为服务器实际暂存 5 小时，页面提示 4 小时；以 `2026-10-15-image-retention-notice-design.md` 和当前部署文档为准。

用户已同意本站异步任务、服务器暂存图片、自动恢复，并明确扩展到所有生图线路。范围包括 VIP 与画布的文生图、参考图与编辑；不改变视频和提示词工具、不自动退款历史账单。

## 可观察效果

- 已完整接收的提交快速返回任务编号；生成不依赖浏览器保持长连接。
- 用户断网、切换标签、刷新或关闭页面后，账号下的任务仍可查询，联网后恢复结果。
- 请求尚未完整上传不承诺已受理；响应丢失可按客户端请求编号查询，安全重发同一请求不会再次生成或扣点。
- 网络查询失败属于连接恢复状态，不等于生成失败。真实任务失败与退款由服务器结算。
- 原生同步/异步均包装为同一本站任务响应；保留各线路的模型、尺寸、参考图兼容处理。

## 后台与持久化

新增独立 imageJobStore / imageJobService，复用现有三个生成处理器及线路适配。任务持久化到 MySQL（生产），文件存储作为现有无数据库运行模式的后备。使用用户与客户端请求编号唯一约束；请求指纹不一致返回 409。任务队列限制并发与待执行量，支持按账号查询，杜绝跨账号读取。提交返回 202 + task_id，查询仅返回小 JSON 和图片地址。

任务保存 endpoint、requestId、userId、状态、费用关联、内部/上游任务编号、生成记录编号、错误、结果地址、保存状态、创建/完成时间。上传参考图与排队请求不允许无界累积在内存。已完成任务不保存完整 Base64 响应。队列无需新增 Redis 服务。

状态：queued -> running -> succeeded / failed；运行中返回内层异步编号则由后台继续查询。连接失败可以继续查询；明确上游失败或最终生成期限届满才失败结算。结果已成功而数据库/保存失败不能被改成上游生成失败。提交幂等与费用关联在后台保存；已运行请求不会在服务重启后盲目再次调用上游。原生上游任务可恢复查询；无法追踪的中断同步任务终结并对本站费用执行一次性退款。进程停止产生的未知结果不能宣称仍必然生成成功。

现有扣点 / refundPoints / settlePendingTask 的幂等结算继续使用；jobId 写入费用元数据，chargeId/accountId 和 generationRecordId 与任务绑定。故障补偿可重复执行但不会重复退款。定时结算不依赖用户打开页面。

## 图片与速度

新 imageJobAssets 模块保存所有线路的结果。完整图片数据已到本站，只增加落盘；生成小预览并通过 URL 返回，避免 JSON 中重复携带原图。远程 URL 可立即提供结果，原图在后台下载，成功后更新为本站 URL，明确 storageStatus 保存中/已保存/保存失败。持久卷保存 72 小时，过期标明且保留用户本地缓存；首次安全写入任务凭据不等于图片永久保存。原图下载、缩略图制作、自动下载与画布预览独立，不阻塞任务提交。下载并发、大小、超时、重试次数、磁盘保留、私有地址访问与目录边界受限，保存失败可重试而不重复生成。

图片地址使用绑定用户、任务和文件的有效期签名；任务接口先验证账号，再提供图片地址，图片元素无需附加登录请求头。原图/预览保存后的地址更新另写紧凑恢复日志；短暂数据库故障或重启后补写，不重复生图。

## 前端

所有三个 API 提交函数发送 asyncTask=true、固定 clientRequestId（每张任务独立），适配 taskId。Gemini 原生调用也能返回任务编号并交给全局查询，不再只接受 images。未获确认的提交按 requestId 查询并重发同一次请求；未获确认显示结果未确认，恢复逻辑保留凭据。本地持久化任务编号/请求编号到账号范围内，重新登录/加载/联网/标签恢复时查询；查询失败不写永久红色生成失败。后台确认 failed 才失败；联网恢复不再重复提示本地网络错误。VIP 复用现有提交/画廊查询能力，画布恢复节点与请求编号匹配，不把旧账号任务混入当前账号。
