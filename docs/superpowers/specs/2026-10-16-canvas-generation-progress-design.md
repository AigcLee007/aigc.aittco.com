# 画布生成进度恢复

用户已确认采用“真实进度优先、预估进度兜底，同时保留等待耗时”。

- 每个生成占位同时显示百分比、紫色进度条、真实任务状态和已等待时间。可靠上游进度显示 `65%`，预估显示 `预计 65%`。
- 上游不同层级的 progress / percent / percentage 数字和百分数字符串归一化；单独的 0 / 100 不视作可用中间进度。成功必须同时具备成功状态和有效结果；失败响应的 100 不得当作成功。
- 预估进度从 generationStartedAt 计算，最多 95%，超过三分钟提示等待较久。没有任务 ID 的同步提交也有预估反馈。只有明确的队列状态才显示排队。
- 节点和悬浮提示共用计算和每秒时钟，悬浮提示读取最新节点。估算只在展示层计算，不每秒写 Zustand / IndexedDB。仅可见生成节点与可见提示订阅时钟。
- 刷新保留开始时间、真实中间进度和任务状态；移出视口再移回不重新计时。旧数据缺少开始时间时，节点、悬浮提示和持久化共用稳定的迁移起点。
- 视频与批量图片沿用各自已有的内部轮询，通过统一回调传递已接收、排队、生成状态和真实中间进度，避免任务已接收却一直显示“正在提交”；不增加第二套轮询。
- 成功有有效结果后结束生成并加载资源，读取期间显示“正在加载图片”。失败、结果缺失、30 分钟等待期限及避免重复提交的提示沿用现有逻辑。
- 不改变经典版、计费、提交接口、上游请求频率和图片缓存生命周期。

验证覆盖：归一化边界、真实/预估选择、长时间与刷新连续性、失败 100、同状态进度更新、共享任务、时钟清理、存储恢复和画布实际渲染。
