# 画布稳定布局与批量生图工作台设计

日期 2026-11-21

状态 待用户评审

## 背景

当前生成入口在创建占位节点时会把所有未锁定图片重新交给自动网格排布，并把视口移到新节点。图片缓存完成后，节点高度还会按原图宽高比调整。画布坐标重排、相机移动和图片框尺寸修正叠加后，生成一张图片也可能让用户感觉整个画布发生了变化。

现有批量弹窗支持导入提示词和多张参考图。模型与线路沿用创作侧栏当前选择，文生图可以重试失败提示词，图生图为每张图执行同一个提示词。图生图没有逐图状态，重新运行会再次提交所有参考图。弹窗内没有模型线路选择、批次费用预估和持久化的任务管理。

本设计将画布位置规则与批量任务执行分别定义。批量工作台向画布写入可追踪的结果节点，画布不会因这些节点的创建而重排旧图。

## 设计目标

- 新生成的图片不改变现有图片的画布坐标。
- 单张和批量结果使用相同的无重叠落位规则。
- 视口移动发生在用户明确开始生成或定位批次时，任务完成顺序不会持续推动画布。
- 文生图和图生图任务均可配置模型、线路、规格、输出数量，并显示逐项状态。
- 图生图明确支持逐张独立处理和多张共同参考两种任务语义。
- 批次关闭或页面刷新后能够恢复任务记录，且不会重复提交已经受理的任务。

## 画布稳定落位

### 坐标与排布

创建生成节点时保留所有既有节点的 `x`、`y`、`width` 和 `height`。新增节点根据请求画幅预留画布框，再从当前视口附近的锚点开始执行确定性的空位搜索。候选位置按稳定顺序向外扩展，检查候选框与现有图片、视频以及本批次已预留框的相交情况。节点之间保留固定间距。

单张生成只搜索并分配一个位置。批量生成先按输入顺序为全部任务及输出数量预留位置，再启动并发队列。单个任务完成时间不会决定结果位置，因此节点不会因不同模型耗时而重新排列。每个结果节点仍可单独拖动和变换。

手动“整理画布”继续执行网格排布，作为显式操作。该操作仅重排未锁定节点。新增图片不调用整理逻辑，锁定状态仍表示用户禁止移动该节点。

### 图片尺寸

占位框按所选画幅确定。生成结果按比例完整显示在该框内，使用 contain 布局，不拉伸图片，也不裁掉画面。上游实际尺寸与所选比例不同时，框的宽高保持不变，框内可能出现留边。用户可以手动调整节点框。

### 视口行为

单张生成开始后，视口可定位到该新节点一次。批量生成创建好整批占位节点后，视口最多定位到批次区域一次。后续进度更新和图片完成事件不改变视口。

工具栏提供“定位到批次”操作。批次较大时，该操作定位到批次起始区域，并保持当前缩放比例，避免为了显示所有任务而把画布缩得过小。

## 批量工作台

### 页面结构

批量入口打开独立的全屏工作台。页面由三部分组成。

- 左侧显示草稿、运行中、已完成和暂停的批次，可创建、切换、复制和删除批次。
- 中央显示当前批次的任务表格、输入、结果、状态和单项操作。
- 右侧显示批次级生成配置、并发和预计费用。

工作台顶部提供文生图、图生图和全部批次导航。返回画布不会清除批次状态。

### 批次配置

新建批次默认带入当前创作侧栏的模型、线路、画幅和尺寸。工作台允许修改模型和线路。图生图模式只显示声明支持图片编辑的模型及线路。当前批次启动时保存一份设置快照，运行期间配置不可变更。用户需要不同配置时可以复制批次或新建批次。

批次级设置包括模型、线路、画幅、输出尺寸、默认每项输出张数、并发数和自动下载偏好。并发选项为 1、3、6，实际派发仍遵守服务端运行限制。

预计费用按每项任务的模型线路单价、输出数量和可用的尺寸费率合计。费率未知时明确显示“暂不可估算”。任务完成后记录实际计费信息。

### 文生图

保留 `.xlsx`、`.xls`、`.docx` 和 `.txt` 导入能力。导入后显示解析预览。Excel 允许选择工作表和提示词列。Word 按非空段落拆分，文本按非空行拆分。

每条提示词生成一项任务。批次级默认输出张数可被单行覆盖。每行可编辑提示词、输出张数和是否参与本次运行。导入内容保持为草稿，用户确认后再提交。

### 图生图

默认模式为逐图独立处理。每张参考图创建一项任务，继承批次共享提示词。用户可以为单张图覆盖提示词和输出张数。

共同参考模式允许用户把多张图片选为一个任务组，并为该组设置提示词和输出数量。工作台需要清晰显示组内参考图片，避免用户误把多图组理解为多项独立任务。

参考图片以本地资产标识持久化，不将大型 data URL 写入批次元数据。单图读取失败只影响对应任务，并在任务行提供重新读取或移除操作。

### 任务状态与操作

单项任务状态包括草稿、待运行、提交中、等待确认、排队中、运行中、成功和失败。批次状态包括草稿、运行中、暂停和已完成。所有任务进入成功或失败终态后，批次标记为已完成，并显示成功和失败数量。

启动按批次任务顺序派发，遵守并发设置。任务行显示当前状态、进度、错误摘要和结果数量。成功任务提供预览、下载和画布定位。失败任务可单独重试，也可批量重试所选失败项。继续批次只派发待运行或用户明确选择的失败项。

暂停只停止后续派发。已经被服务端受理的任务继续运行并更新为完成或失败。工作台关闭或页面刷新不会隐式重提受理任务。恢复时优先按已保存的 `clientRequestId` 查询受理状态，待运行任务仅在用户恢复批次后继续派发。

服务端明确返回队列满时，任务保留为待运行并显示原因。请求结果因临时网络错误无法确认时，任务进入等待确认，工作台使用原 `clientRequestId` 查询服务端状态。已成功任务不会因恢复、重试或刷新而再次提交。

### 批次与画布结果关联

每个批次任务保存生成节点 ID、客户端请求 ID、服务端任务 ID、输入资源 ID、提示词快照、模型线路快照、任务状态和结果节点 ID。批次视图中的结果操作可定位回画布中的对应节点。

画布结果按预分配位置写入。一个批次结果区域可以一次定位，完成顺序不改变其空间位置。批次结果默认是独立节点，不自动绑定拖动。用户可以使用画布的多选和分组功能自行组织。

## 数据与执行边界

批次和任务元数据存入 IndexedDB。参考图片使用现有本地资产存储，批次只引用资源 ID。任务请求继续使用现有图片任务客户端、请求 ID、服务端任务 ID和全局轮询恢复能力。

队列协调逻辑由工作台组件生命周期之外的批次服务管理。页面关闭时，已受理任务继续由服务端执行，尚未派发的任务留在本地批次中。应用重新打开后可恢复受理任务状态，用户确认继续后再派发余下任务。

开始批次前校验模型线路对当前生成模式的支持情况、图片资源可读性、输出数量和费用数据。验证失败的任务保留在清单中并提供逐项原因，不提交整批请求。

## 最终用户流程

1. 用户从画布工具栏打开批量工作台并新建批次。
2. 用户选择文生图或图生图，导入提示词或添加参考图片。
3. 用户检查任务映射，选择模型线路和默认规格，并确认预计费用。
4. 用户启动批次，在任务表中观察运行、成功和失败状态。
5. 用户暂停、编辑待运行任务或只重试失败项。
6. 成功结果写回画布批次区域，用户可从工作台定位并继续编辑。

## 验收标准

- 新建单张图片后，所有既有节点画布坐标保持不变。
- 手动移动未锁定图片后再次生成，移动后的坐标继续保留。
- 批次中所有输出都有预留位置，任务完成顺序不会改变节点坐标。
- 请求画幅与原图比例不一致时，原图完整显示且节点框不自动改尺寸。
- 单张生成最多自动定位一次，批量任务不会在每个节点完成后推动视口。
- Excel 导入可选择工作表和提示词列。Word、文本拆分结果可预览和编辑。
- 图生图可分别运行单张任务，也可将多张图片组成共同参考任务。
- 每项任务可查看状态、结果或失败原因。重试失败项不会重提成功项。
- 暂停后在途任务正常结算，待运行任务保持待运行。
- 关闭并重新打开工作台可恢复批次状态和任务映射，已受理请求不会重复提交。
- 工作台仅提供当前模型线路支持的图像生成模式。
- 批次结果可定位回画布，画布手动布局不因结果写入而改变。

## 实施边界

本设计包含稳定画布落位、独立批量工作台、批次持久化、任务恢复、费用预估、模型线路能力筛选和结果关联。实现阶段需要拆分为画布位置算法、批次数据与执行服务、工作台界面和跨刷新恢复四个部分，并分别验证。
