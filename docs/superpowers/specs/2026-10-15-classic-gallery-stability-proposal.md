# 经典版生成区与画廊稳定性处理方案

状态：已按用户授权实施，待服务器更新。排查基准为分支 codex/image-async-recovery、提交 501de9c，结合用户提供的 5 张截图；实施验证见 docs/classic-gallery-stability.md。此次没有访问用户浏览器缓存，也没有用线上付费任务复现。

## 用户应得到的效果

生成两张动物运动会图片时，之前的滕王阁序图片留在原位置。任务查询、图片暂存和预览补齐只更新对应卡片。打开画廊先出现已有本地记录和预览，后台核对服务器；核对失败不清空已有图片。经典版提供与画布一致的自动下载原图开关，并区分浏览器缓存、云端暂存和系统文件下载。

## 已确认的问题与证据

1. `public/classic-app/script.js:677` 的 persistClassicLiveTasks 按 updatedAt 降序重排整个任务数组。updateClassicLiveTask、completeClassicLiveTask 等都会刷新此时间。`public/classic-app/unified-bridge.js:2437` 附近的恢复逻辑对已成功任务仍调用 completeClassicLiveTask；恢复在页面 focus、online 和每 30 秒触发。用原函数在 Node VM 中复现：初始顺序 animal-1 / old-calligraphy，更新旧任务后变为 old-calligraphy / animal-1，再查询新任务又变回原顺序。
2. `public/classic-app/unified-bridge.js:2213` 的 renderRemoteHistoryGrid 先释放已有图像绑定并清空 historyGrid，再等本地/服务器记录合并后重建全部卡片。生成区 renderClassicLiveTasks 也先清空容器，随后重新附加卡片。画廊称为 incremental 的请求最后仍进入全量重绘。
3. `public/classic-app/script.js:396` 的 setClassicImageState 只要收到 ready 就把徽标设为“已本地保存”。`public/classic-app/image-runtime.js` 中独立预览的读取路径不会保存原图，持久化异常又被忽略。原运行时模拟验证：仅远程预览可用、预览写入抛出配额异常时，返回仍为 ready / remote，原图写入次数为 0。该标识无法证明原图已缓存，更无法证明文件已下载到系统文件夹。
4. 经典版成功处理路径没有接入自动文件下载；downloadSingleImg 由用户点击调用。画布 useGenerationLogic 的 autoDownloadOnSuccess 默认开启，使用原图队列下载。截图中的下载记录不能单独证明对应图片已经由经典版下载。
5. 经典版 acquire 对准备队列也计入整体超时。用缩小时间比例的模拟验证：3 张图片各处理 20ms、整体期限 30ms 时结果为 ready / failed / failed；后两张会因为等待前面的工作超时。该机制可以造成假性读取失败，但截图里的每一张失败图片是否由此触发还需浏览器运行日志确认。
6. 经典版与画布使用不同 IndexedDB 资产格式。经典版历史又用随机历史 ID、remote ID 和完整 URL 合并；临时上游地址变为本站地址时，不能稳定识别同一张图片。经典版首次拿到结果后会停止生成查询，后续原图/预览暂存更新可能只出现在恢复查询；已有同 URL 历史记录又不会补齐新预览。

## 推荐路线与备选

用户已授权直接实施全部方案。本次合并交付固定身份、局部更新、本地优先、原图缓存/下载及经典版与画布共享存储，保留既有记录与兼容读取路径。

只改排序能快速减少跳动，但不能解决反复读取和原图丢失。完整重写经典版界面范围更大，会与已有生成、账号和恢复流程交织；此次采用有针对性的列表与资产服务调整。

## 第一阶段：固定身份与位置，更新卡片而不重建列表

- 新任务按不可变提交时间倒序，同批次按输出序号排列；相同时间以固定 ID 作次序。保留用户当前选中卡片和滚动位置。
- 使用 ownerId + 本站 jobId + outputIndex 关联结果。旧任务用已有记录 ID 和明确的任务关联迁移，不通过相同提示词猜测身份。URL、签名和预览地址是可更新属性。
- 完成时间只在首次成功转换时确定，恢复成功任务不得写成当前时间。没有实际字段变化时不触发渲染。
- 生成区和画廊使用固定键定位卡片；进度更新只改状态文本，预览更新只替换对应图片。清空、移除卡片时才释放其图像租约。
- 多输出任务逐张登记，不能只取 resultUrls[0]。临时地址切换到本站地址时保留卡片与本地资产身份。
- 合并历史写入使用单一写入队列或事务中的 upsert，避免两张图同时完成时读旧数组再覆盖彼此的记录。记录淘汰只按明确缓存策略处理。

## 第二阶段：先恢复本地，再核对远程

- 页面启动后先读取当前账号的本地记录和预览，再异步请求服务器。API 慢、断网或请求失败时继续显示已有记录。
- 同一账号的历史请求合并，使用请求代次避免旧响应覆盖新响应。生成成功、回到前台等事件合并触发更新。
- 远程只补充新任务和已知任务的图片保存状态；只按 createdAt 拉新增不足以获取旧任务的 previewUrl/storageStatus 变化。首次成功后对保存仍 pending 的任务继续有限查询；保存成功、失败或到期后停止。
- 网络核对不释放现有可用预览。刷新整个网页后 Object URL 需要重建，但优先从本地 Blob 重建，不要求重新下载所有原图。

## 第三阶段：原图缓存与自动下载

- 新生成结果一旦可用，就进入原图缓存队列，不以是否打开画廊为条件，手机同样执行受限队列。任务生成成功与本地保存失败分别表示。
- 原图 Blob 事务提交后记录 originalCached；预览提交后记录 previewCached。只缓存了预览时明确标记“仅预览已缓存”。缓存满、数据库暂不可读等情况显示真实原因并保留记录。
- 同一原图的缓存、下载、预览制作共享一次读取。保存和下载本身不反复解码 4K 原图；需要制作预览时才在受限队列解码。
- 经典版加入“生成成功后自动下载原图”开关，默认开启，与画布设置保持一致。逐张下载，文件名包含提示词和稳定任务/输出标识。
- 普通浏览器下载调用只标记“已发起下载”，不宣称已确认落盘。用持久化下载意图与跨标签领取避免普通刷新/重复任务查询再次自动下载；不能把下载调用之后的崩溃当成可精确判断的完成事件。提供手动“下载原图”和“下载未处理原图”入口。
- 页面关闭期间由服务器继续生成；用户在云端期限内回来后补缓存与下载。浏览器缓存仍可能被用户或浏览器清理，不能承诺永久保存。

## 第四阶段：共享存储、控制内存并兼容旧图

- 在现有画布资产机制上建立共同的资产身份和存储适配，经典版与画布为同账号同结果共享原图/预览；保持两版界面的任务列表独立。
- 从经典版 images/previews 和画布现有资产记录建立可验证的映射，优先复用已存在 Blob，迁移成功前保留旧记录。旧数据无法确定归属时不自动关联给当前账号。
- 借鉴 D:/gpt-iamge-2 的固定图片身份、原图/缩略图分开保存、数据库连接复用和任务创建时间排序。保持 Blob 存储，避免把大图转换成 Base64 在列表中传递。
- 桌面画廊每页 24 张、手机每页 12 张；可见区外少量预取。预览网络并发上限 3，原图缓存/下载队列上限 1，预览解码上限 1。
- 队列等待显示“等待读取”，实际执行才开始网络/解码超时；队列自身必须有容量与等待期限，并允许离屏取消、重新排队，避免转成无限等待。
- 加入总字节预算、使用中保护与明确的回收策略。缓存配额不足时优先回收可再获取的旧缓存；云端已失效且仅剩本地的一份原图不能静默淘汰。
- 读取状态区分网络异常、缓存暂不可读、损坏和云端过期；失败只重试该图。预览已可用但原图失效时保留预览。重试读取不再次发起付费生成。
- 原图只在下载、放大、编辑时按需读取并释放；页面列表只显示预览。切换页面正常释放不可见资源，不靠所有原图常驻内存掩盖问题。

## 页面文案

- 原图事务成功：原图已缓存（本浏览器）。
- 只有预览持久化：仅预览已缓存，请下载原图。
- 本站暂存可读但本地无原图：云端暂存 · 请尽快下载。
- 下载 API 已调用：已发起下载 · 请查看下载记录。
- 云端过期且本地无原图：原图已过期 · 从本地文件恢复。
- 云端提醒继续展示 4 小时，后台实际保留 5 小时缓冲。服务器清理不删除用户下载文件，也不顺带删除浏览器本地原图。

普通网页不能在没有用户选择/授权的情况下自动扫描下载文件夹。增加“从本地恢复”文件选择入口；允许用户选回已有原图。以后可单独提供支持浏览器上的授权文件夹模式，目录写入结果可确认，权限丢失时明确提示并回退。

浏览器限制依据：https://developer.chrome.com/docs/capabilities/web-apis/file-system-access

## 验收场景

1. 同时生成两张动物运动会，交替查询、触发 focus/online/30 秒恢复；滕王阁序位置、完成时间和图片绑定保持不变。
2. 同一任务返回上游地址、本站地址及稍后预览；画廊中只有对应输出的一张卡片，下载始终读取原图。
3. 同时完成多张图，记录和 Blob 均存在；恢复和重复完成通知不会重复自动下载。
4. 预览可用但原图未缓存、IDB 写入失败、配额不足分别核对徽标，不能显示已缓存原图。
5. 本地已缓存图片在断网、刷新、云端过期后仍可查看/下载；没有缓存的过期图明确显示到期，支持用户选择本地文件恢复。
6. 加载 50/100 张 4K 结果，滚动并切换生成区/画廊；只读取所需预览，排队不能误报损坏，解码并发不超过 1，内存不随来回切换持续增长。
7. 原图下载设置关闭/开启、刷新、两个标签页同时恢复均符合下载策略；浏览器拦截下载时保留手动入口，不能误报落盘成功。
8. 服务器历史慢/失败以及旧响应晚到不清空本地列表；账号切换不混入其他账号的图或缓存任务。

实施顺序：身份与排序 → 卡片局部更新与本地优先恢复 → 原图缓存及自动下载 → 共享存储与旧图迁移 → 大量图片与网络/配额异常验收。
