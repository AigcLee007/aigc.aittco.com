# GPT-Image-2.5 双线路接入实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox ( - [ ] ) syntax for tracking.

**Goal:** Add one gpt-image-2.5 model with gpt-image-2.5-flare and gpt-image-2.5-sunburst routes, both using the existing PixelleLabs GPT image endpoint, API key, and GPT-Image-2-compatible request format.

**Architecture:** Keep one model record and two route records. The model owns the shared GPT parameter controls and 1K/2K/4K sizes; each route owns its upstream model name, but both routes reuse the current PixelleLabs URL, synchronous mode, point price, and IMAGE_ROUTE_GPT_IMAGE_2_LINE2_KEY. A shared compatibility predicate will be used by the backend and equivalent predicates in both UIs so the new upstream names enter the existing GPT generation and edit branches.

**Tech Stack:** TypeScript, React, vanilla JavaScript classic UI, Express/CommonJS, JSON catalogs, Vitest, Docker.

- [x] **Step 3: Implement the pure predicate**

Create imageModelCompatibility.cjs:

~~~js
const GPT_IMAGE_COMPATIBLE_PATTERN = /^gpt-image-2(?:$|-|\.5(?:-|$))/i;

const isGptImageCompatibleModel = (value = '') => {
  const normalized = String(value || '').trim();
  return normalized === 'seedream-5-pro' || GPT_IMAGE_COMPATIBLE_PATTERN.test(normalized);
};

module.exports = {
  GPT_IMAGE_COMPATIBLE_PATTERN,
  isGptImageCompatibleModel,
};
~~~
